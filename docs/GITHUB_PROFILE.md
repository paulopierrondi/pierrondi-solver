## Repository standard

Every flagship repository should ship with:

- a product-specific 1280×640 social preview;
- one-sentence promise before implementation detail;
- working proof or screenshot;
- five-minute quickstart;
- architecture and failure model;
- explicit limitations and responsible-use boundary;
- CI, contribution guide, security policy, support guide, and issue forms;
- package/repository metadata;
- a small `PIERRONDI / LABS` publisher signature.

## Solver public settings checklist

- Description: keep the current integrated, local-first positioning.
- Topics: keep `ai-agents`, `automation`, `browser-automation`,
  `captcha-solver`, `cloudflare`, `fastapi`, `hcaptcha`, `playwright`,
  `recaptcha`, `self-hosted`, `turnstile`, and `whisper`.
- Social preview: upload `assets/brand/github-social-preview.jpg`.
- Verify Actions after push.
- Recheck the Community profile after GitHub indexes the new files.

Changing the public profile, pushing, or uploading the social preview remains a
separate public action requiring explicit approval.
